# Case: `layout`

The fixture record for the packaged-FMU listing. It says what the bytes cannot:
which archive shape is contractual, which oracle checks it, and what may be
normalized.

- **Conversion:** staged FMU directory (`modelDescription.xml`,
  `binaries/linux64/Tank.so`, `sources/tank.h`, `resources/`, `documentation/`)
  → deterministic `.fmu` zip
- **Requirement / fault:** the FMI 2.0 checklist requires
  `modelDescription.xml` at the archive root, the binary at
  `binaries/linux64/<modelIdentifier>.so` with execute bits, sorted entries, and
  `FMI_EPOCH` timestamps. A packager that preserves source mtimes, drops the
  executable bit, or writes `modelDescription.xml` under a directory still
  produces a zip every tool may reject at load.
- **Level:** component
- **Input:** synthesized inline by `tests/test_package.py::make_inputs` for
  identifier `Tank` — a fake ELF payload, one generated header, one resource
  directory with a nested file, one loose resource, one documentation file, and
  a model description serialized by the `pyssp_standard` codec (1 input,
  1 output, one `CoSimulation` interface). No external source or licence
  obligation.
- **Expected:** the committed `listing.txt`, which records the archive sha256 on
  its first line and then `mode`, `size`, `timestamp`, `name` for every entry
- **Independent oracle:** `pyssp_standard.common.archive.archive.package_archive`
  writes the archive and `zipfile.ZipFile` reads it back; the test asserts
  `namelist()`, permissions, and timestamps independently of the writer.
  `Fmi2ModelDescriptionXmlCodec().parse` confirms the source document is valid
  FMI 2.0 before packaging.
- **Comparison:** exact text against `listing.txt`; the archive sha256 in that
  listing is the byte-level gate, so any layout, mode, timestamp, or content
  change is visible in one reviewed line
- **Normalization:** none. Every entry is stamped `2000-01-01T00:00:00` by
  `FMI_EPOCH`, entries are written in sorted order, metadata files are `0o644`,
  and files under `binaries/` are `0o755`; no wall-clock value enters the zip.
- **Volatile fields:** none. The model description is generated from fixed
  inline data, the binary and resources are fixed bytes, and the clock is the
  FMI epoch rather than the generation time.
- **Update policy:** `UPDATE_GOLDENS=1`, read the diff, commit the test input
  change and the listing together; refused when `CI` is set
- **Notes:** the digest in `listing.txt`
  (`ad826bfff00415851e4a9f135eca40dd31530427335e7b5023af9d85201f7b63`) also
  proves two fresh stages repack to the same bytes. Deflate output depends on the
  zlib used to build the interpreter, so the listing is regenerated only in the
  documented environment, not across arbitrary zlib versions.

## What this case proves

If the case is deleted, a regression in the archive contract has no remaining
byte-level coverage. The other tests assert individual properties (byte identity
across repacks, optional `resources/` and `documentation/`, rejection of a
mismatched identifier or platform); only this listing pins the complete entry
set, its order, its permissions, and its timestamps together, and records the
digest that a changed entry would move.
